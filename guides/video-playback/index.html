FULL SYSTEM VIEW

Two ways to play the same clip

The first route already starts before full download. HLS adds quality choices; the CDN serves repeated requests.

01 / PROGRESSIVE MP4

Playable MP4 → HTTP origin → browser video element → initial bytes → decoded first frame

A seek may request a later byte range. The origin needs correct MP4 delivery and range support.
02 / HLS PREPARATION

Source video → encoder: 360p / 720p / 1080p → aligned segments + playlists → object storage

Upload the media first. Publish playlists and mark the clip ready after every referenced file exists.
03 / HLS PLAYBACK

Browser player → CDN → master playlist → chosen media playlist → init + segment → decoder

Later requests can choose another quality or time. A CDN miss fetches from storage; a hit serves cached bytes.

Trace this clip: 90-second source → clip.mp4 → /hls/clip/master.m3u8 → 720p/index.m3u8 → 720p/init.mp4 + 720p/seg000.m4s → first frame Paths, bitrates, resolutions, and a four-second target are examples. This guide follows on-demand video.

BUILD IT IN STAGES

Each stage solves a new problem

The HLS path is a second delivery design for the same clip, introduced only after the MP4 works.

01 / WORKING

Progressive MP4

Encode a browser-compatible MP4, move its metadata forward, serve it with range support, and confirm that first-frame playback and seeking work.

02 / VARIABLE NETWORKS

HLS variants

Encode several rates, cut aligned segments, publish playlists, then let the player fetch and switch future segments by network conditions.

03 / MANY VIEWERS

CDN and recovery

Cache immutable segment files close to viewers. Measure startup and stalls, retry short network failures, and report missing packages.

Three states that should not be mixed up

Published All files named by the playlists exist.

Buffered The player has media for a span of playback time.

Playing The decoder is producing pictures and sound.

A 200 response for a playlist does not mean any frame has decoded. A full file download is not required for playback.
Exact progressive MP4 exchange

Page: <video controls preload="metadata" src="/media/clip.mp4"></video>. The preload value is a browser hint.

Possible request: GET /media/clip.mp4 with Range: bytes=0-1048575. A browser may also make a plain GET or choose another range.

Range response: 206 Partial Content; Content-Range: bytes 0-1048575/12000000; Content-Type: video/mp4. The next request can ask for another range. If the origin ignores Range, it may return 200 with the whole file.

Seek: For 00:45, the browser uses MP4 sample timing and keyframes to locate a useful byte position. Time is not converted to bytes by a simple percentage.

What the HLS files contain

master.m3u8: #EXTM3U followed by an #EXT-X-STREAM-INF entry for each quality, including BANDWIDTH, CODECS, and RESOLUTION, then that quality's media playlist URL.

720p/index.m3u8: #EXTM3U, #EXT-X-VERSION:7, #EXT-X-TARGETDURATION:4, #EXT-X-PLAYLIST-TYPE:VOD, #EXT-X-MAP:URI="init.mp4", then #EXTINF:4.000, and seg000.m4s. Later segments follow. An on-demand playlist ends with #EXT-X-ENDLIST.

720p/init.mp4: fMP4 initialization data. seg000.m4s: encoded media for an opening time span. The player needs both before it can decode that fMP4 segment.

Boundary check: A four-second target does not guarantee every segment is exactly four seconds. Put suitable keyframes at intended cut points and check that variant timelines align.

How a player chooses the next file

Start: Get the master playlist, select a supported bitrate, get its media playlist, then request init data and the first segment. A native HLS stack or JavaScript player feeds the decoder.

Continue: Keep some media ahead of the playhead. Compare measured download rate and buffer with each variant's bitrate. Request a lower or higher quality for a future aligned segment.

Seek: Find the segment whose time span includes the new position, fetch from a decodable boundary, and discard or replace unneeded buffered data. The exact buffer policy belongs to the player.

Browser support: Native HLS and MSE-based players differ by browser and device. Test the actual codecs and player path you ship.

Failure drill and measures

MP4 starts slowly: Check codec support, MP4 metadata location, origin response, first-byte time, and first-frame time separately.

HLS segment is slow: If buffer is shrinking, choose a lower bitrate for a later segment; retry a transient request with a finite limit.

Segment is 404: Check publication order, object path, playlist URL, and CDN cache. A lower bitrate only helps if its matching segment exists.

Decode fails after a switch: Inspect codec declarations, timestamps, keyframes, and the matching init file for both renditions.

Measure: play-to-first-frame time, startup failure rate, rebuffer count and duration, selected bitrate, segment HTTP status, CDN hit rate, and seek delay.

Key terms

Progressive MP4 One MP4 delivered over HTTP; playback may begin before its full body arrives.

Range request An HTTP request for selected bytes of a file.

Keyframe A frame suitable for starting video decoding without earlier predicted frames.

HLS HTTP Live Streaming: playlists point to short media segments.

Rendition / variant One encoded quality of the same timeline, such as 720p at a stated bitrate.

fMP4 Fragmented MP4: an initialization section plus media fragments.

Adaptive bitrate Choosing later segments at a bitrate that fits current conditions.

CDN A network of caches that can serve repeated HTTP files closer to viewers.

Sources and scope
